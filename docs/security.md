# Security and privacy controls

**Synthetic data only.** These controls are *HIPAA-inspired*: they follow the same ideas
(minimum necessary data, access control, audit, encryption) but are not a compliance claim.
The AI is decision support; a clinician makes every decision.

## Patient data

| Control | Where |
|---|---|
| Personal details (names, phone numbers, emails, locations, SSNs) are removed **before** symptom text reaches the AI | `services/triage-service/app/redaction.py`, tested in `tests/test_triage.py` |
| Symptom text is **never stored**; only the structured triage result is | `POST /intake`, tested (`test_symptom_text_is_not_stored`) |
| Symptom text is **never logged**, before or after redaction; logs and metrics carry only metadata (urgency, entity types, timings) | both services; tests check logs and `/metrics` |
| The clinician queue shows "Patient 0007", not names or emails (minimum necessary) | `GET /queue` |
| The AI result is always labelled "AI suggestion · clinician decides"; every decision records who made it (`reviewed_by`) and when (`reviewed_at`) | frontend, `PATCH /triage/{id}` |
| Lab reports: critical values come from **fixed rules**, not the AI; the AI sees only extracted rows (never the report's name/DOB/record number) and can raise but never lower the lab urgency | `triage-service/app/labs/` |
| Lab results and explanations reach a patient **only after a clinician approves**; patients never see "critical" wording | `appointment-service/app/labs.py`, frontend |
| Uploaded reports are kept in a private Blob container (no public access, no account keys) under a generated name; the original file name isn't stored | `azure.tf`, `app/storage.py` |
| If the AI fails or answers badly, the intake gets "soon, review manually", never a silent "routine" | `parsing.py`, `ai_client.py`, `app/triage.py` |

## Access control

| Control | Where |
|---|---|
| Every endpoint except `/health` needs a signed token; roles `patient`, `clinician`, `admin` | `app/auth.py`, `tests/test_auth.py` |
| Patients only see and act on their own appointments (others get 404, so existence isn't revealed) | `GET /appointments`, `POST /intake` |
| Cloud sign-in uses Microsoft Entra External ID (email verified at sign-up); tokens are verified against the tenant's keys (signature, issuer, audience, expiry) | `AUTH_MODE=entra-external-id`, tested with real RS256 tokens |
| A token can never change an existing user's role; staff roles come from operator-controlled `CLINICIAN_EMAILS` / `ADMIN_EMAILS` | `app/auth.py` |
| Demo sign-in (`/auth/dev-login`) exists only when `AUTH_MODE=dev` | tested |

## Infrastructure

| Control | Where |
|---|---|
| No cloud keys anywhere: GitHub → Azure via OIDC; pods → Key Vault and Azure OpenAI via workload identity; Azure OpenAI has key auth turned off | `infra/terraform`, `infra/k8s/overlays/aks` |
| The only real secret (database password) is generated by Terraform and kept in Azure Key Vault (RBAC) | `azure.tf` |
| The database has no public endpoint: it lives in a delegated subnet of the cluster's virtual network, with TLS required | `azure.tf` |
| HTTPS for the whole app (Let's Encrypt on the ingress); frontend and API share one origin, so no CORS is needed | `ingress.yaml` |
| Pods (including the nginx frontend) run as non-root with a read-only filesystem, no capabilities, seccomp | `infra/k8s/base` |
| The triage service is internal; a NetworkPolicy lets only the appointment service reach it | `network-policy.yaml` |
| `/metrics` isn't reachable from the internet (nginx and ingress return 404) | `nginx.conf`, `ingress.yaml` |
| A monthly budget with alerts at 25/50/80/100 % | `azure.tf` |
| CI runs lint, tests, image builds, a full docker compose flow, Kubernetes on kind and Terraform validation on every pull request | `.github/workflows/ci.yml` |
| Secrets never committed: `.env` and `*.tfvars` are git-ignored; pre-commit runs `detect-private-key` | `.gitignore`, `.pre-commit-config.yaml` |

## Known limits

- Redaction is a spot-checked safeguard, not a guarantee (see `docs/triage.md`): unusual names or
  identifiers like insurance numbers may be missed. That's why only synthetic data is used.
- Dev tokens are signed with a shared secret and last 8 hours. They're for local demos only.
- The demo runs one AKS node and a burstable PostgreSQL server: fine for a course, not highly
  available.
